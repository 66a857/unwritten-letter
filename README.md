# 未署名 · GitHub Pages 版本

保留原匿名信箱的信纸、信封和浅绿色风格。网页由 GitHub Pages 托管，来信由 Supabase 保存。写信人无需账号；查看和删除来信需要专属管理密钥。管理密钥只保存在自己的浏览器中，换设备时可导入备份恢复。

## 部署

1. 在 GitHub 账号下创建名为 `unwritten-letter` 的公开仓库，初始化 README，默认分支为 `main`。
2. 在专用的新 Supabase 项目执行 `database.sql` 一次。它会建立私有数据表和受控 RPC，匿名用户不能直接读取数据表。
3. 将项目 URL 和 publishable key（或 anon public key）填写到 `config.js`。不要填写 secret key 或 service_role key。
4. 上传本目录下全部源码到仓库根目录。在 GitHub 仓库 Settings → Pages → Source 选择 GitHub Actions。
5. 等待 Publish anonymous letter website 工作流成功，使用部署返回的网址。
6. 打开页面创建信箱，立即备份管理密钥。分享「复制写信链接」生成的链接，勿分享管理密钥。

## 验收

- 手机和电脑浏览器、微信内置浏览器均能加载写信页；也能连接 Supabase。
- 在设备 A 创建信箱并备份密钥。在未登录、未保留存储的设备 B 通过公开链接投稿；设备 A 刷新后能看到来信。
- 用错误管理密钥读信应失败；不带管理密钥应无法读取或删除来信。
- 用正确密钥导入设备 C 应能读取该信箱；其他信箱的密钥不能读取该信箱。
- 提交空白和超长正文应被拒绝。正文里的 HTML 应显示为普通文字，不执行。
- 删除来信后刷新不应再显示；不把测试信件保留在正式信箱。

## 数据边界

应用不要求写信人提交姓名、微信号、账号或联系方式。数据库不存储写信者 IP；托管服务可能保留其访问日志。创建限流为全站每小时 50 个信箱，每个信箱每分钟最多 10 封信；需要更大用量时应在服务端调整并增加反滥用措施。管理密钥遗失无法找回，密钥泄露等同于信箱访问权限泄露。每次收信显示最新 200 封。
